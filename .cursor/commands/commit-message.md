# 未コミットの変更からコミットメッセージを検討する

作業ツリーの未コミットの変更を読み、`.cursor/rules/commit-message.mdc` に従ったコミットメッセージを提案する。コミットはしない。

## 手順

1. 規約を読む
   - `.cursor/rules/commit-message.mdc`

2. 変更を集める
   - `git status --short`
   - `git diff --staged`
   - `git diff`
   - 未追跡ファイルは中身を読む。
   - 直近の履歴を `git log --oneline -n 10` で確認し、scope の付け方を既存のコミットにそろえる。

3. 変更の目的を整理する
   - 変更を目的ごとに分類する。
   - `docs/roadmap.md` で今回完了にした項目があれば、その目的と照らし合わせる。
   - 目的が複数あるときは、1コミットにまとめず、目的ごとにメッセージを分ける。
   - ステージ済みの変更がある場合は、ステージ済みの分を1コミットとして扱い、未ステージの分は別に扱う。

4. メッセージを書く
   - コミットごとに、規約の形式でメッセージを1案だけ書く。
   - 本文には、diff から読み取れる理由、または roadmap と `docs/design-notes.md` に書かれている理由だけを書く。理由が読み取れないときは本文を推測で作らず、要約だけにする。

5. 出力する
   - コミットメッセージ案のコードブロックだけを出力する。変更の一覧、コマンド例、type の別案、補足の説明は出さない。
   - 分割が必要な場合だけ、各コードブロックの直前に、そのコミットに含めるファイルを1行で書く。

## 守ること

- `git add`、`git commit` は利用者が指示したときだけ実行する。
