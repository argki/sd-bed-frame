# 次のコミット単位を実装し、コミットメッセージまで出す

`next-commit.md` と `commit-message.md` をこの順で続けて実行する。どちらも `git commit` はしない。

## 手順

1. `.cursor/commands/next-commit.md` に従い、roadmap の次の1項目を実装する。報告まで行う。
2. 手順1の報告で「`/commit-message` で検討できる」と伝えない。続けてメッセージを出すためである。
3. 手順1のあと、作業ツリーに未コミットの変更があることを確かめる。
   - 変更がなければ、実装できなかった理由を報告して終える。コミットメッセージは出さない。
   - 未コミットの変更が、手順1とは別の目的のものだけなら、作業を始めずに利用者へ報告し、先にコミットするか確認する。メッセージは出さない。
4. `.cursor/commands/commit-message.md` に従い、手順1で生じた未コミットの変更からコミットメッセージを検討する。
5. 出力は次の順にする。
   - 先に、`next-commit.md` の報告（実装した内容、確認した内容と結果、確認できなかった内容）。
   - そのあと、`commit-message.md` の形式でコミットメッセージ案のコードブロックを出す。

## 守ること

- `git commit`、`git push` は実行しない。
- `git add`、`git commit` は利用者が指示したときだけ実行する。
- 1回の実行で扱うのは roadmap の1項目だけにする。
- `next-commit.md` と `commit-message.md` の「守ること」も、それぞれ該当する手順で守る。
