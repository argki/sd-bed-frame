# 作業計画

1項目を1コミットの単位とする。`/next-commit` は最初の未完了項目から進める。

- [x] Cursor 用のルールとコマンドを追加
  - 完了条件: `.cursor/rules/`、`.cursor/commands/`、この roadmap がある

- [x] Vite + React + TypeScript の雛形を作成
  - 完了条件: pnpm、Vite、React、TypeScript（strict）、Tailwind CSS、Biome、Vitest の設定があり、空のトップページが表示できる。`.gitignore` がある

- [x] Docker Compose で開発、プレビュー、フォーマット、lint、テストを実行できるようにする
  - 完了条件: `dev`、`preview`、`format`、`lint`、`test` の各サービスが動く。`preview` は GitHub Pages と同じ base パスで動く

- [x] 設計定数と部材の型を定義
  - 完了条件: マットレス寸法、ダンボール寸法、1x4 の断面と長さ、価格、カット代、カットロスが `src/design/` にある。部材（名前、長さ、本数、3D 上の位置と向き、所属モジュール）を表す型がある

- [x] 4分割ベースのフレーム設計を作成
  - 完了条件: ダンボールが収まる内寸を満たすモジュール設計が部材データとして定義され、内寸がダンボール寸法と余裕を満たすことをテストで確かめている。設計判断を `docs/design-notes.md` に書いている

- [x] 木取りと費用の計算を追加
  - 完了条件: 部材リストから 12f 材の必要本数、材ごとの木取り、カット回数、材料費、カット代、合計を計算できる。計算のテストがある

- [x] 部材リストと費用のページを追加
  - 完了条件: 部材ごとの寸法と本数、購入本数、費用の内訳が表示される

- [x] カット寸法図を追加
  - 完了条件: 12f 材1本ごとの木取りが SVG で表示され、各部材の長さと端材の長さが読める

- [x] 組み立て済みの 3D モデルを追加
  - 完了条件: 部材データから 3D モデルを生成し、回転、拡大縮小して見られる。ダンボール箱を収納した状態も表示できる

- [x] 3D の爆発図を追加
  - 完了条件: 組み立て済みと分解状態をスライダーで切り替えられる。モジュール単位でも分解して見られる

- [x] ネジ止めの位置と留め方を定義
  - 完了条件: どの部材どうしを、どの面から、何で何本留めるかが `src/design/` にある。判断を `docs/design-notes.md` に書いている

- [x] 中央の上横桟を柱で支える
  - 完了条件: 中央の上横桟の両端が柱または受け材に接し、その接触にもネジ止めが定義されている。接していることをテストで確かめている

- [x] ネジ止めを3Dと購入リストに表示
  - 完了条件: 3Dで留め位置と留め方が分かる。購入するネジの種類、本数、費用がページに出る。数値は `src/design/` から読む

- [x] 3Dの部材にカット寸法図と同じ名称を表示
  - 完了条件: 組み立て済みと分解状態の両方で、天板のすのこ、柱、上横桟、下横桟の名称が3D上で読める。表示する名称は部材データの名前を使い、画面に別の名前を直書きしない

- [x] 各部材に種類ごとの連番を付ける
  - 完了条件: 天板のすのこ、柱、上横桟、下横桟のそれぞれで、1本ごとに1からの連番が付く。カット寸法図と3Dの印字が同じ連番を使い、画面側に別の番号を直書きしない

- [x] 部材分解で境の部材が重ならないようにする
  - 完了条件: 部材モードで分解を100%にしたとき、隣のモジュールと境で接している柱どうし、天板のすのこどうしが重ならない。柱22と16、柱23と17、柱10と4、柱18と24、天板のすのこ10と5、天板のすのこ20と15が、それぞれ離れて読める

- [x] モジュール同士を繰り返し外せる連結にする
  - 完了条件: 4つのモジュールを互いに留める方法が `src/design/` にある。外して付け直しても、コーススレッドの打ち直しで穴が弱くならない。モジュール同士はコーススレッドで固定しない。判断を `docs/design-notes.md` に書いている

- [x] モジュールの連結を3Dと購入リストに表示する
  - 完了条件: 3Dで、どのモジュールどうしをどこで留めるかが分かる。購入するものが増える場合は、種類、数、費用がページに出る。ボルト、ナット、座金の税込価格は、ビバホームの掲載に合わせた値を `src/design/` に置く。数値は `src/design/` から読む

- [x] GitHub Pages へのデプロイを追加
  - 完了条件: main への push で GitHub Actions が build、lint、test を行い、GitHub Pages に公開される

- [x] リポジトリ直下の README を整備
  - 完了条件: 公開 URL、ローカルでの起動方法、フォーマット方法、設計の前提が書かれている。文章は yomiyasu スキルで推敲している

- [x] 各ディレクトリに README.md を置く
  - 完了条件: ソースや設定を置くディレクトリ（`.cursor`、`.cursor/commands`、`.cursor/rules`、`.github`、`.github/workflows`、`docs`、`src`、`src/components`、`src/design`）に README.md があり、そのディレクトリの概要が書かれている。文章は yomiyasu スキルで推敲している

  - 完了条件: いまの 1x4 のみの設計と、2x4 や金物を組み合わせた案について、金物を除く木材の点数を比較している。点数を減らせるかどうかと、採用するか見送るかの判断を `docs/design-notes.md` に書いている。採用する場合は、使う断面、金物、部材構成の案も同メモに書いている。この項目では設計データの差し替えと画面の更新はしない
